# Cooperative Task Scheduler using Timer1 ISR

A lightweight cooperative task scheduler for AVR/Arduino using **Timer1 Compare Match Interrupts**.

This project demonstrates how to build a simple embedded scheduler without using an RTOS.
Tasks execute periodically based on a global system tick generated by a hardware timer interrupt.

---

## Features

* Timer1 interrupt-based system tick
* Cooperative task scheduling
* Function pointer task execution
* Periodic task handling
* Lightweight and RTOS-free
* Easy to scale for small embedded systems

---

## How It Works

### 1. Timer1 Generates System Tick

Timer1 is configured in **CTC (Clear Timer on Compare Match)** mode.

Every timer compare match:

* `TIMER1_COMPA_vect` interrupt fires
* Global variable `tick` increments

```cpp
ISR(TIMER1_COMPA_vect)
{
    tick++;
}
```

This creates a software time base for scheduling tasks.

---

### 2. Task Structure

Each task contains:

```cpp
struct Task {
    uint32_t period;
    uint32_t last_run;
    void (*function)();
    uint8_t enabled;
};
```

| Field      | Description              |
| ---------- | ------------------------ |
| `period`   | Task execution interval  |
| `last_run` | Last execution tick      |
| `function` | Function pointer to task |
| `enabled`  | Task state               |

---

### 3. Scheduler Loop

The scheduler continuously checks whether a task is ready to execute.

```cpp
if ((current_tick - tasks[i].last_run) >= tasks[i].period)
```

If enough time has passed:

* task executes
* `last_run` updates
* scheduler continues checking remaining tasks

This is called a **cooperative scheduler** because tasks voluntarily return control after execution.

## Timer Configuration

### Prescaler

```cpp
TCCR1B |= (1 << CS11) | (1 << CS10);
```

Prescaler = 64

---

### Compare Value

```cpp
OCR1A = 2500;
```

For a 16 MHz clock:

```text
16,000,000 / 64 = 250,000 Hz
2500 counts = 10 ms
```

So:

* 1 scheduler tick = 10 ms

## Why Cooperative Scheduling?

Advantages:

* Very lightweight
* Easy to debug
* Minimal RAM usage
* No context switching overhead

Limitations:

* Long tasks block other tasks
* No task priorities
* No preemption

This approach is commonly used in:

* Small AVR systems
* Sensor polling
* UART command systems
* Low-resource embedded projects
